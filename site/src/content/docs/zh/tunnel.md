隧道让内网服务（NAS、内网应用、数据库管理页）**无需开放任何入站端口、也不需要
公网 IP** 即可被访问：连接器主动向外拨号，边缘负责公网一侧。WAF 已有的全部能力
（规则、限流、挑战、缓存、访问控制、日志、证书、回源 TLS）都照常生效——对边缘
而言，隧道就是一个普通源站。

本页是完整的操作说明：各个部件是什么、让隧道跑通的五个步骤、请求如何流转、连接器
有哪些命令、完全没有直接出网时怎么用，以及出问题时的排查顺序。

## 部件

| 部件 | 运行位置 | 职责 |
| --- | --- | --- |
| **连接器**（`wafred-tunnel`） | 内网主机 | **只出站**连接控制面与边缘；把每条被代理的连接转发到内网目标 |
| **边缘监听** | WAF 边缘（`tunnel_addr`，端口 `9443`） | 接受连接器的 TLS 会话，并为每个目标开一个回环桥 |
| **桥接** | 边缘上的 `127.0.0.1:<临时端口>` | 让隧道在代理看来就是一个普通源站 |
| **源站池绑定** | 控制面 | 指定站点流量可以经该隧道访问哪些内网 `host:port` |

隧道**不是** VPN：它只承载绑定到它的源站池的流量。一个隧道即一个信任域——任何
服务该隧道所绑定站点的边缘，都能向连接器请求该隧道目标清单中的任意地址。

## 适用场景

- 源站位于 NAT 或无法（不打算）开放端口的防火墙之后。
- 源站地址只在内网有意义（`10.0.0.5:8080`、`app.internal:8443`）。
- 公网入口必须留在 WAF 上，而不是内网主机上。

不要把它当通用出网代理：当前版本经站点承载 HTTP、HTTPS 与 WebSocket，暂不暴露
裸 TCP（SSH、任意端口）。

## 三个必须区分开的状态

控制台把它们分开显示，绝大多数误解都来自把三者混为一谈：

| 状态 | 含义 | 来源 |
| --- | --- | --- |
| **已配对** | 凭据已存在，隧道可用 | 连接器兑换配对令牌时写入 |
| **已启用** | 运维的按隧道开关 | `PATCH /tunnels/{id}` 的 `status` |
| **连接器在线** | 当前有连接器持有控制流 | 控制面实时上报 |

隧道可以「已配对 + 已启用」而连接器离线——那是"配置正确但连接器没跑"，不是坏
了；反过来不可能在未配对的情况下「连接器在线」。

## 五步让隧道跑通

### 1. 创建隧道

**边缘节点 → 隧道 → Create tunnel**。控制台会创建隧道并显示一次性配对命令：

```bash
curl -fsSL https://raw.githubusercontent.com/oyport/wafred/main/install.sh \
  | sudo bash -s -- --mode tunnel \
      --server-url https://control-plane:9090 \
      --server-ca-cert control-plane.pem \
      --token <pairing-token>
```

令牌**只显示一次**，默认 30 分钟后过期（`pairing_ttl_seconds`）。再次生成会轮换
凭据并断开正在运行的连接器，所以在复制完命令之前不要关闭弹窗——关闭后只能重新
配对。

### 2. 在内网主机上运行连接器

该命令会安装 `wafred-tunnel`、用令牌换取长期凭据、写入 `/etc/wafred/tunnel.toml`
（`0600`）并注册 `wafred-tunnel.service`。

不用安装器时，手工等价操作：

```bash
sudo wafred-tunnel pair \
  --config /etc/wafred/tunnel.toml \
  --server-url https://control-plane:9090 \
  --server-ca-cert /etc/wafred/tunnel-ca.pem \
  --token <pairing-token>
sudo wafred-tunnel run --config /etc/wafred/tunnel.toml
```

`run` 会与控制面保持一条控制流（用于策略、刷新会话令牌与吊销），并与每个边缘入口
各保持一条会话。连不上任一端时它会在 `warn` 级别打日志——这正是
`journalctl -u wafred-tunnel` 里要找的那行。

### 3. 在某个边缘开启监听，并给它一个公网地址

至少一个边缘需要接受隧道连接：

```toml
# 公网边缘上的 wafred.toml
[agent]
tunnel_addr = "0.0.0.0:9443"
```

或用 `--tunnel-addr 0.0.0.0:9443` / `WAFRED_TUNNEL_ADDR`，并在边缘防火墙上放行
`9443`。边缘首次启动时自签证书（持久化，重启后指纹不变）、上报其 SHA-256，连接器
固定该指纹。

compose 部署时，该变量必须写进服务的 `environment:` 块——compose 只传递服务声明的
环境变量，仅放在 `.env` 里不会进入进程。仓库自带的 `docker-compose.yml` 已转发
`${WAFRED_TUNNEL_ADDR}` 并发布 `${WAFRED_TUNNEL_BIND:-127.0.0.1}:9443:9443`；
连接器在其他主机上时设 `WAFRED_TUNNEL_BIND=0.0.0.0`，并在云安全组与主机防火墙
同时放行 `9443`。

然后在 **边缘节点 → [节点] → 隧道入口** 填写该边缘的**隧道入口地址**——连接器
拨号的公网 `host:port`。面板同时显示监听状态，并会说明"已配置但绑定失败"（例如
端口被占用）。

监听器在启动时绑定，修改 `tunnel_addr` 需要重启边缘。入口**地址**与隧道策略是热
生效的：通过下一次推送到达连接器与边缘（连通时 ≤5s），因此更换入口地址或重新配对
都不需要重启。

### 4. 把源站池绑定到隧道

**站点 → [站点] → 源站池 → [池] → Tunnel**。池里的节点地址就是连接器要拨的内网
目标；边缘自己不会去拨这些地址，而是把回环桥地址交给该池。

当没有任何边缘持有会话时，绑定隧道的池没有上游；指向它的路由返回 `503`，而不是
回退到站点的默认源站——请求绝不能悄悄落到另一个后端。

### 5. 验证是否真的通了

按失败顺序检查三项：

1. **连接器在线** —— **边缘节点 → 隧道** 中该行显示「已配对」「连接器在线」，
   详情面板的 **边缘节点** 至少有一条。本机可用
   `sudo wafred-tunnel status --config /etc/wafred/tunnel.toml` 看到同样的实时
   状态：已连接的入口、生效的目标、SOCKS5 代理（若配置）以及最近一次吊销原因。
2. **边缘提供入口** —— 详情面板能看到边缘与 **目标**；**边缘节点** 为空说明没有
   边缘开启监听或未填入口地址（回到第 3 步）。
3. **站点经隧道可达** —— 以站点自己的 Host 访问：

   ```bash
   curl -sv -H 'Host: app.example.com' https://<边缘地址>/ \
     --resolve app.example.com:443:<边缘地址>
   ```

   返回源站的 `200` 即全链路正常；`502/503` 说明边缘没有会话（回到第 1 步）或
   连接器到不了源站（日志里是 `target is unreachable`）。

详情面板的 **使用该隧道的站点** 列出绑定它的站点——也就是禁用或删除它的影响面。

## 请求如何流转

```
客户端 ──TLS──► 边缘 :443 ──► WAF 流水线 ──► 源站池（已绑定隧道）
                                                │
                                     127.0.0.1:<桥接端口>
                                                │
                                       TLS + 多路复用会话
                                                │
                                       连接器（内网）
                                                │
                                       10.0.0.5:8080（源站）
```

因为桥接就是一个普通源站，请求链路里没有任何特殊分支：WAF 照常判决、缓存照常命中、
日志照常记录，访问日志会把源站显示为 `tunnel://<名称>/<目标>` 而不是回环端口。
连接器只接受控制面下发的目标清单（可被本地 `allowed_targets` 进一步收紧），因此
边缘无法让它拨该隧道策略之外的地址。

## 连接器命令

```bash
wafred-tunnel pair   --token <pairing-token> --server-url https://cp:9090 [--config PATH]
wafred-tunnel run    [--config PATH]
wafred-tunnel status [--config PATH]
```

| 配置项 | 含义 |
| --- | --- |
| `tunnel_id`、`credential` | 由 `pair` 写入 |
| `server_url`、`server_ca_cert`、`server_tls_name` | 控制面及其 TLS 信任 |
| `ingress` | `host:port[=sha256]` 入口；由控制面下发，也可在本地固定 |
| `allowed_targets` | 可选本地白名单，与策略取交集（绝不合并） |
| `socks5_proxy`、`socks5_username`、`socks5_password` | 经 SOCKS5 代理出网 |
| `session_token` | 给边缘的短期令牌，由控制面刷新 |

`status` 不会另开控制面流——那会占掉正在服务流量的连接器的会话位。它读取 `run`
发布到 `/var/lib/wafred/tunnel/status.json` 的状态。

## 不出网：通过 SOCKS5 代理

只能经 SOCKS5 代理出网的主机（跳板机、企业网关）同样可用：指定代理后**两条通道**
——控制面流与所有边缘会话——都走它。

```toml
socks5_proxy    = "10.0.0.1:1080"     # 或 socks5://user:pass@10.0.0.1:1080
socks5_username = "connector"          # 可选
socks5_password = "…"                  # 可选
```

- 目标主机名**由代理解析**（SOCKS5 ATYP 3）——内网里出问题的往往正是本地 DNS。
- 凭据可写在 URL 中；显式键优先，密码建议用 `WAFRED_TUNNEL_SOCKS5_PASSWORD`
  传入，避免被 `ps` 看到。
- 不会静默回退直连：需要代理的主机直连本来就不通，代理卡住时拨号会失败并指出卡在
  哪一步。

## 运维动作

| 动作 | 效果 |
| --- | --- |
| **重新配对**（`POST /tunnels/{id}/pairing`） | 轮换凭据、断开当前连接器、给出新的一次性命令 |
| **吊销**（`POST /tunnels/{id}/revoke`） | 清除凭据；边缘在下一次规则包（≤5s）后拒绝该隧道，连接器停止 |
| **禁用**（`PATCH /tunnels/{id}`） | 按隧道开关；在线会话在下一次 reload 时关闭 |
| **删除**（`DELETE /tunnels/{id}`） | 仍被源站池引用时返回 `409`；`?force=true` 才会清空绑定，这些池回退为**直连**源站 |
| **设置**（**隧道 → 设置**） | 部署级：总开关、配对令牌有效期、单会话流数、单隧道目标数、会话存活、心跳、会话令牌有效期 |

## 安全模型

- **边缘永远看不到连接器凭据。** 连接器出示的是控制面用 Ed25519 签发的**短期
  会话令牌**（密钥由部署的 `jwt_secret` 派生）；边缘用规则包中的公钥校验签名、
  隧道 id 与有效期。
- 被截获的令牌在有效期（默认 1 小时，`session_token_ttl_seconds`）后失效，也无法
  用于其他隧道。
- **连接器固定边缘证书**（SHA-256），不匹配即失败关闭。
- **吊销在边缘可连通控制面时收敛**：规则包移除该隧道的公钥，下一次 reload 即拒绝。
  与控制面分区的边缘沿用最后一次策略，与本部署对规则本身的 fail-open 一致。
- 桥接端口仅监听回环；边缘主机可信，与任何本地代理一致。

## 排查

| 现象 | 检查 |
| --- | --- |
| 连接器日志 `cannot reach the control plane` | `server_url`、`9090` 可达性、CA（`--server-ca-cert`）或 SOCKS5 代理 |
| 控制台「连接器在线」但「边缘节点 0」 | 没有边缘开启 `tunnel_addr`，或其**隧道入口**为空（第 3 步） |
| 会话被拒 `the tunnel credential was not accepted` | 令牌过期/被吊销，或边缘尚未收到新公钥——连接器会带新令牌重试 |
| 站点返回 `502/503` | 边缘没有会话，或连接器到不了目标（日志 `target is unreachable`） |
| 池显示 `127.0.0.1:<端口>` 源站 | 正常：那就是桥接端口，会话重连后端口会变 |
| 删除被 `409` 拒绝 | 仍有源站池引用；先解绑或传 `?force=true` |
| `status` 显示 `not running` | 连接器未运行，或还没发布状态文件 |
| 边缘日志 `cannot start the tunnel listener` | 端口被占用或无权限；节点详情面板会给出同样原因 |

## 本版本的限制

- 经站点承载 HTTP、HTTPS 与 WebSocket；不暴露裸 TCP。
- 一个隧道即一个信任域（见上文）。
- 单隧道目标数与单会话流数由设置行限制。
- 监听器启动时绑定；策略与入口地址热生效。
