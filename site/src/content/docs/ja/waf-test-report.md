## 結果の概要

2026-11-22に、ローカルで再ビルドしたWAFred 1.0.4候補版と公開chaitin/blazehttpコーパスでテストしました。HTTPリクエストは33,877件（悪意ある658件、正常33,219件）です。ブロックとチャレンジを攻撃の検知数に含め、正常通信への影響にも両方を含めます。

| ティア | 攻撃サンプルの検知 | 正常通信への影響 | リプレイ p50 / p95 | HTTP 500 |
|---|---:|---:|---:|---:|
| Normal | 397/658（60.33%） | 4/33,219（0.012%） | 43 / 48 ms | 0 |
| Normal + ボディ検査 | 494/658（75.08%） | 12/33,219（0.036%） | 43 / 48 ms | 0 |
| Strict | 501/658（76.14%、ブロック491・チャレンジ10） | 4/33,219（0.012%） | 43 / 48 ms | 0 |
| Strict + ボディ検査 | **632/658（96.05%、ブロック622・チャレンジ10）** | **19/33,219（0.057%）** | 43 / 48 ms | 0 |

## 漏れの原因と修正

以前のリプレイはコーパスのバイト列をそのまま送っていました。`Content-Length` と `Transfer-Encoding` がないボディ付きリクエストは、サーバーにはボディなしとして届き、ボディ検査の効果を低く見積もっていました。現在は正確な長さを補い、1つの有効な長さを超える余分なバイトを切り詰めます。この変更により、不正な長さを持つ15件の正常リクエストがプロキシ転送時にHTTP 500となる問題も解消し、全ティアでHTTP 500は0件です。

WAFredは、明確なフォーム構造がある `Content-Type` 未指定のURL-encoded/multipart本文、Base64エンコードされたパスセグメントを解析し、Strict専用に `alert.call` / `prompt.call` のシグネチャを追加しました。Strict + bodyは632/658件を検知しました。正常リクエスト19件（ブロック17、チャレンジ2）に影響したため、このティアを有効にする前に確認してください。

Strict + bodyで未検知の26件は、HTTP 200で通過した23件、HTTP parserが400で拒否した2件、method layerが405を返した1件でした。修正前バイナリとの同一条件比較では、Strictは500から501件、Strict + bodyは630から632件に増えました。追加の正常リクエスト誤判定と検知の後退はありません。残りの攻撃サンプルは固定回帰セットに残し、アプリケーションの実際の経路と合わせて調べます。

## 他製品との過去データ比較

グラフでは、WAFred 1.0.4の今回の測定値を、PingWAF時代の最終P13実測およびSafeLine、ModSecurity、Cloudflareの過去データと並べています。前回は同じ名目コーパスを使いましたが、body framingの方式が異なり、今回のハーネスではframingに起因するHTTP 500を15件修正しました。これは記録された各バージョンの結果であり、条件を統制した前後比較ではありません。他製品は再テストしておらず、母数とネットワーク経路も異なります。WAFredのp95にはVM、プロキシ、模擬オリジンが含まれるため、遅延を直接比較できません。

## 圧縮本文とHTTPS

gzipテストでは、ボディ検査なしは0/8件、Normal + ボディ検査は7/8件、Strict + ボディ検査は8/8件を検知しました。正常リクエスト2件は全ティアで通過しました。

隔離したHTTPSリスナーでは、`wafred-test.local` と `127.0.0.1` 用の自己署名証明書を使用しました。`curl --cacert` による明示的な検証は成功し、既定のcurl信頼ストアは想定どおり証明書を拒否しました。OpenSSLのSNIハンドシェイクはTLS 1.2/1.3で成功しました。正常なHTTP/HTTPSは200、HTTPS上のフォーム攻撃とBase64パス攻撃は403でした。TLSはWAFredで終端し、模擬オリジンにはHTTPで接続しています。

## 性能と対象範囲

256同時接続の3分テストと512同時接続時のファイル記述子の検証は、修正候補版ではなく元の配置済みバイナリで測定しました。元プロセスは `nofile=1,024` で512同時接続時にGETで30件、POSTで68件の502を返しました。分離したコピーで65,536にすると502はありませんでした。稼働中のall-in-oneプロセスは変更していません。

セキュリティテストは隔離したHTTP/1.1プロキシと模擬オリジンを使用しています。実アプリケーションオリジン、HTTP/2/HTTP/3、本番ルーティング、rate limiting/CC、候補版の高負荷テストは未実施です。詳細は[WAFred 1.0.4 完全レポート](https://github.com/oyport/wafred/blob/main/docs/wafred-baseline-test-report-2026-11-22.md)を参照してください。
