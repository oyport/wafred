# WAFred 1.0.4 内部测试记录

本轮沿用此前 WAFred 版本测试的语料和逐样本归因方法。以下数据来自 2026-11-22 本地重建的 WAFred 1.0.4 修复候选版本，SHA-256：93b4b6e92e39eb3417dabec510945fe847667660ffad0493c1a3f31d50fc9796。

## 当前全量结果

Strict + body 检查拦截或质询 632/658 个恶意样本（96.05%），正常样本受影响 19/33,219（0.057%），其中 17 条拦截、2 条质询。其他档位及测试方法见[对外实测报告](waf-test-report.md)和[完整实验室报告](../wafred-baseline-test-report-2026-11-22.md)。

## 漏拦截归因

表面漏报中占比最大的原因是语料 framing 不完整。部分样本有请求体字节，却没有 Content-Length 或 Transfer-Encoding；旧回放器仍发送这些字节，但 HTTP/1.1 不会把它们作为请求体交给 WAF。修复后的回放器会为这类夹具补齐准确的请求体长度。仅有一个有效 Content-Length 时，声明长度以外的字节会被丢弃。重复/无效长度与 Transfer-Encoding 夹具仍保持原样，用于协议测试。

另有 15 条正常夹具在有效 Content-Length 后带有额外字节，旧回放器因此触发代理 HTTP 500。修正 framing 后，四档测试都不再出现这些 500。

候选版本增加了未声明类型 URL-encoded 和 multipart 请求体的有界检查、Base64 路径分段解码，以及仅在 Strict 档启用的高危 alert.call 与 prompt.call 签名。

## HTTPS 与容量说明

隔离 HTTPS listener 使用自签证书，并由 curl --cacert 显式信任。TLS 1.2/1.3 SNI 握手验证通过；HTTP/HTTPS 正常请求均返回 200，HTTPS 表单与 Base64 路径探针返回 403；未信任测试 CA 的客户端按预期拒绝证书。

256 并发、3 分钟稳态数据（5,172 RPS、931,266 个 2 KiB POST、0 错误）及 512 并发文件句柄问题来自原部署二进制，不能代表修复候选版的高并发性能。候选版本没有部署到生产 all-in-one 进程。
