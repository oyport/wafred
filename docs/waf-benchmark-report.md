## 漏拦截归因与修正

部分攻击夹具包含请求体字节，但缺少 Content-Length 和 Transfer-Encoding。旧回放器仍发送这些字节，HTTP/1.1 却不会把它们交给 WAF 作为请求体，导致这些样本被记作漏报。现在回放器会为非空且无 framing 头的请求体补齐准确 Content-Length；只有一个合法 Content-Length 时，会截掉声明长度之后的尾字节。重复/非法长度和 Transfer-Encoding 夹具保持原样，用于协议测试。

另有 15 条正常夹具在声明长度后带有额外字节，旧回放造成代理返回 HTTP 500。修正 framing 后，四档测试的 HTTP 500 均为 0。

WAFred 检测侧增加未声明类型 URL-encoded/multipart 请求体的有界字段解析、Base64 路径分段扫描，以及 Strict 专用的 alert.call 和 prompt.call 高危签名。原部署构建与修复候选版本在相同 framing 下对比，Strict 多识别 1 条、Strict + body 多识别 2 条攻击；未丢失已有命中，也没有新增正常样本拦截或质询。

## HTTPS 与容量说明

候选版本在隔离 listener 上使用自签证书测试 HTTPS，证书 SAN 为 wafred-test.local 和 127.0.0.1。curl 通过 --cacert 显式信任证书，TLS 1.2/1.3 握手验证通过；正常 HTTPS 请求返回 200，表单与 Base64 路径攻击探针返回 403。未信任测试 CA 的客户端按预期拒绝证书。测试上游模拟源站使用 HTTP。

256 并发三分钟稳态测试完成 931,266 个 2 KiB POST，吞吐 5,172 RPS、错误为 0；512 并发文件句柄问题来自原部署二进制的复核，不代表修复候选版高并发性能。候选版本尚未部署到生产 all-in-one 进程。详细漏报样本、TLS 参数、机器分工与归档信息见[完整实验室报告](./wafred-baseline-test-report-2026-11-22.md)，简要版见[WAF 实测报告](./waf-test-report.md)。
