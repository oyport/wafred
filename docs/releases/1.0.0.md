# WAFred 1.0.0 首次发布

发布日期：2026-11-08。

WAFred 是基于 Apache-2.0 许可的 [PingWAF](https://github.com/shuaiZend/PingWAF) 代码库继续独立开发的项目。本页汇总本次发布相对于该代码来源的**功能新增与行为变更**；原项目的历史版本不代表 WAFred 的发布版本。代理层还继承自 [pingap](https://github.com/vicanso/pingap)，其网络底座是 [Pingora](https://github.com/cloudflare/pingora)。版权和许可说明见 [NOTICE](../../NOTICE)。

## 新增功能

### 站点路径限制

在站点的「访问限制 → 路径限制」中，可以按前缀、精确路径、通配符或正则表达式匹配请求，并组合 WAF 表达式、规则优先级和 IANA 时区的每周生效时段。路径限制优先于路径例外。

规则可立即阻止访问，或按每个客户端 IP 在指定计数窗口内的请求次数触发阻止，并设置持续时间。计数在各生效节点本地进行；普通阻止只返回拦截响应，不会将 IP 加入黑名单。规则也可要求站点已配置的 Basic 认证，或将选定路径交由 OIDC 登录保护。Basic 凭据和 OIDC 提供方仍需先在该站点完成配置；使用 OIDC 路径限制时，应将 OIDC 认证范围设为「仅路径规则触发」。

### 彩虹DNS 证书验证

在「SSL/TLS → 申请或上传证书」中，DNS-01 验证新增「彩虹DNS」提供商。填写管理端地址、用户 UID 和 API 接口密钥后，WAFred 在签发时创建 ACME 所需 TXT 记录，并在验证后清理。现有 DNS 提供商仍可使用。

### Agent 连接排障

Agent 连接控制面失败时，日志现在针对明文/TLS 协议不匹配、不受信任的 CA、证书 SAN 不匹配及网络不可达给出诊断提示。安装脚本也会提示远程 Agent 使用 HTTPS、CA 证书和必要时的 TLS 名称。

## 行为变更与修复

- 产品命令和发布物统一为 `wafred`；服务名、容器镜像、配置路径与数据路径使用 WAFred 标识。
- OIDC 可以只保护被路径限制规则选中的路径，回调和身份提供方入口仍可访问。
- 未匹配 Host 的自定义 HTML 错误页恢复模板变量渲染。
- 后台表格为操作列保留合理宽度，在窄屏使用横向滚动，避免按钮文字被挤成多行。
- 代理底座升级到 Pingora 0.9.1。

## 从 PingWAF 迁移

这是 WAFred 的第一个版本，**不提供从 PingWAF 部署自动升级**。旧 `pingwaf` 命令、`PINGWAF_*` 环境变量、服务名、配置和数据路径、数据库标识及 `PINGWAF-*` 托管规则 ID 均不兼容；请按 [部署文档](../deployment.md)在新环境安装 WAFred，并在迁移策略和数据前单独备份、核对标识。不要将旧数据库或规则覆盖文件直接挂载到新实例。

发行标签为 `v1.0.0`。Linux 安装包和校验文件由 [GitHub Release](https://github.com/oyport/wafred/releases/tag/v1.0.0) 提供；构建完成前请以该页面实际列出的文件为准。
